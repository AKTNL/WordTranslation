# PaperDict 段落翻译体验设计

## 目标

修复划词翻译和整页翻译中的三个问题：无 `key` 的合成键盘事件会中断内容脚本；划词卡片不会随原选区滚动；双语和纯中文模式依赖观察器回调且正文识别范围过窄，导致切换后经常没有可见变化。

整页翻译面向论文阅读，采用按段落渐进翻译。双语模式按“英文原段落 + 中文译文”配对展示，纯中文模式保持原文档结构并以译文替代英文正文的可见内容。

## 交互行为

### 划词卡片

- 保存有效选区的 `Range`，而不是只保存弹出瞬间的 `DOMRect`。
- 页面滚动或窗口缩放时，根据实时选区重新计算卡片位置。
- 卡片始终锚定原选区，不吸附在视口边缘。
- 原选区完全离开视口、被清除或对应 DOM 节点失效时，卡片自动隐藏。
- `keyup` 处理器先验证 `event.key` 是字符串，再判断方向键，兼容没有 `key` 的合成事件。

### 双语模式

- 保留英文标题、段落和列表项。
- 每个原文块后插入对应中文译文。
- 译文使用左侧绿色标识线、适度上下间距和“译文”标签，形成清晰但克制的段落分界。
- 单段翻译失败时保留英文，并在对应位置显示失败状态；其他段落继续处理。

### 纯中文模式

- 沿用与双语模式相同的候选识别和译文节点。
- 翻译成功后隐藏对应英文块，只显示中文译文。
- 保留标题层级、列表层级、段落顺序和页面整体布局。
- 单段翻译失败时保留该段英文并显示失败状态，避免正文无故消失。

## 正文识别

候选元素包括 `P`、`H1` 至 `H6`、`BLOCKQUOTE`、`LI`，以及满足正文特征的语义 `DIV`。正文 `DIV` 必须包含足够的英文文本，并且不能只是多个候选子块的容器。

以下内容不参与整页翻译：

- 导航、页眉、页脚、侧栏和菜单
- 按钮、链接集合、输入框和其他表单控件
- `PRE`、`CODE`、脚本、样式、公式及可编辑区域
- 已生成的译文或状态节点
- 不满足英语源文本规则的内容
- 已由更具体子候选覆盖的父容器

候选过滤继续复用现有英语源文本判断与学术页面过滤规则，并增加对语义正文 `DIV` 的支持。

## 翻译调度

采用“首屏立即翻译 + 后续按需翻译”的混合策略：

1. 用户切换到双语或纯中文模式后，立即扫描候选元素。
2. 当前视口内的候选直接进入翻译队列，不等待 `IntersectionObserver` 首次回调。
3. 视口外候选交给 `IntersectionObserver`，在滚动进入视口时排队。
4. 动态网页新增正文时，DOM 监听器发现并注册新候选；已在视口内的新增候选立即排队。
5. 每个候选使用明确状态防止重复排队，并复用现有并发限制、缓存、术语库和引擎选择逻辑。

模式切换和页面重扫必须是幂等的。退出整页模式时移除译文和状态节点，取消英文隐藏状态，并断开本次模式创建的观察关系，使页面恢复到进入模式前的显示状态。

## 组件边界

- `content.js` 负责选区生命周期、卡片定位和键盘事件防御，不承担整页段落调度。
- `bilingual.js` 负责候选识别、视口调度、段落状态、译文呈现和模式恢复。
- 现有消息通道继续负责实际翻译，不新增翻译 API，也不改变引擎优先级或术语库语义。

候选识别、视口判断和卡片几何计算应提取为可独立测试的纯函数或小型辅助单元，避免测试依赖完整浏览器页面。

## 错误处理

- 合成键盘事件字段缺失时直接忽略相关快捷键判断，不影响其他事件逻辑。
- 选区 `Range` 失效或几何信息为空时关闭卡片，不抛出未捕获异常。
- 单个段落翻译失败只更新该段状态，不中止整个队列。
- 模式启动、消息通道或注入失败继续通过现有可见提示反馈，不只写入控制台。
- 观察器不可用时，至少完成当前已扫描候选的立即调度，保证切换模式有可见反馈。

## 测试与验证

实现遵循测试先行，自动化覆盖：

- `keyup` 缺少 `key` 时不抛异常。
- 滚动和缩放后按实时选区重新定位卡片。
- 选区离开视口、清除或失效后隐藏卡片。
- 模式启动时立即排队首屏段落。
- 后续段落进入视口及动态插入时继续排队。
- 正文 `DIV` 可识别，导航、按钮、代码、公式和父子重复块被排除。
- 双语模式生成带左侧标识线和标签的段落译文。
- 纯中文模式隐藏成功翻译的英文，并在失败时保留英文。
- 重复激活、模式切换和退出不会重复节点，且能完整恢复页面。
- 单段失败不阻断其他段落。

完成后运行全量单元测试、诊断测试和语法检查，并在真实 Edge 扩展中验证：划词后滚动、窗口缩放、长论文滚动翻译、动态正文、双语/纯中文切换，以及在线和离线配置下的失败反馈。

## 非目标

- 不翻译网页导航、按钮、表单、代码或公式。
- 不一次性翻译整页全部文本，以避免长论文造成网络拥塞、限流和页面卡顿。
- 不加入译文折叠交互；FAQ 仅作为用户描述的分界参考，最终采用始终展开的段落配对样式。
- 不修改翻译引擎协议、术语库格式或缓存策略。
